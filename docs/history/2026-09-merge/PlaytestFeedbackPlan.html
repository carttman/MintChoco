먼저 읽을 것

따로 적혀 있지만 사실 같은 작업

피드백을 파트별로 갈라보니 항목 4개가 실은 하나의 작업이었습니다. 이걸 먼저 묶으면 전체 일정이 눈에 띄게 줄어듭니다.

① 조준 모드는 하나면 된다 3건 → 1건

꿀풍선(포물선 궤적 → 좌클릭), 디저트 폭격(방향 궤적 → 좌클릭), 히어로 랜딩(착지 원 → 좌클릭)이 전부 “아이템 사용 → 조준 표시 → 좌클릭 확정” 구조입니다.

공통 UItemAimMode 하나에 미리보기 액터와 확정 콜백만 아이템별로 꽂는 형태를 권합니다. 히어로 랜딩의 AimMarkerClass(BP_LandingMarker)가 이미 있어 출발점이 됩니다.

② 차지샷 낙하는 이미 절반 구현돼 있다 신규 → 연출

차지샷은 지금도 광선 아래 바닥을 40 cm 간격으로 최대 256번 찍어 한 줄로 칠합니다(Trail, TrailDropHeight 2000). 즉 “아래로 떨어지는” 도포는 이미 존재합니다.

없는 것은 순차 타이밍과 낙하 연출뿐입니다. 디저트 폭격의 APaintRain이 RowInterval 0.05초로 행을 차례로 떨구므로, 같은 액터를 스나이퍼 샘플 위에 재생시키면 됩니다.

③ 샷건 궤적 도포는 데이터만 채우면 된다 코드 0줄

“탄환이 날아가는 자리가 칠해져야 한다”는 기능은 UPaintballProfile::TrailDeposit으로 이미 구현돼 있고, DA_Paintball_Heavy_Trail이 실제로 쓰고 있습니다.

DA_Paintball_Light는 TrailDeposit.BrushProfile이 비어 있어 꺼져 있을 뿐입니다. 브러시를 채우면 바로 켜집니다.

④ 진영 색은 파라미터 규약 문제 4건 → 1건

꿀벌·디저트 폭격·히어로 랜딩·초콜릿 분수가 모두 “진영별 색”을 요구합니다. 이펙트마다 따로 만들면 4배 일이 됩니다.

NS_PaintSplat이 쓰는 User.TintColor 방식을 모든 진영색 이펙트의 규약으로 정하고, 스폰하는 쪽에서 팀 색을 넣어주는 코드 한 곳만 만들면 됩니다.

결정 대기

진행 전에 정해야 할 것

스위트 스피너 — 기존 샷건 재사용 의견 요청됨

이미 그렇게 돼 있습니다. DA_Weapon_SpinnerVolley는 샷건과 똑같은 PaintGunProfile 클래스이고, 탄환과 산탄 패턴만 다릅니다.

따라서 기존 방식 유지를 권합니다. 새 메커니즘을 만들면 이펙트·애니메이션이 새로 필요하지만, 지금 구조를 유지하면 발사 속도·탄환·산탄 값만 바꿔 원하는 손맛을 낼 수 있습니다. 현재 0.1발/초 · 600 cm/s · 잉크 0 %입니다.

샷건 발사 속도 — 방향 확인 필요

“0.25초 정도 필요”라고 하셨는데, 현재 값이 이미 0.125초(초당 8발)입니다. 0.25초로 바꾸면 지금의 절반 속도가 됩니다.

체감이 더 느리게 느껴지셨다면 발사 속도가 아니라 애니메이션·반동 연출이 원인일 수 있습니다. 의도가 “더 빠르게”인지 “더 느리고 묵직하게”인지 확인이 필요합니다.

무한 탄환 — 차지샷 기준 시간

“차지샷이 2초일 경우 0.5초로”라고 적어주셨는데, 현재 ChargeTime은 3초입니다.

기준을 3초로 보고 버프 후 목표치를 정할지, 아니면 기본 충전 시간 자체를 2초로 낮출지 먼저 정해야 합니다.

“현재” 칸의 모든 수치는 에디터에서 DA_Weapon_* · DA_Item_* · DA_Paintball_* 를 직접 읽은 값입니다. 규모 표기는 기존 구현 재사용을 전제로 한 추정이며, 실제 착수 전에 담당자 확인이 필요합니다.
